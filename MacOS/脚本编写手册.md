# 脚本编写手册（Mac bash 交互式工具脚本约定）

适用范围：Toolbox 里跑在 Mac 上、带交互菜单的 bash 工具脚本。参考实现见
`finder-view.sh`（本手册里的代码片段都摘自这个文件，改的时候直接照抄改名字即可）。

## 环境限制（写之前先知道）

Mac 自带 `/bin/bash` 是 **3.2.57**（没装 homebrew bash），这个版本：
- **没有关联数组**（`declare -A` 是 bash4+ 才有），i18n 查表只能用 `case` 语句，不能用关联数组模拟字典。
- 中文文案里变量名后紧跟全角标点（，。、等）会被吞进变量名触发 `set -u` 报错，一律写 `${var}` 不要写 `$var`。详见 `[[bash32-cjk-punct-var-expansion]]`（Mac 侧记忆）。

每写完一个新脚本，先跑 `/bin/bash -n 脚本.sh` 用系统自带的 bash（不是 Git Bash 或 homebrew bash）过一遍语法，确认在 3.2 下没有用到新版本才有的语法。

## 1. 循环菜单

主菜单是一个 `while true` 循环，每轮重新打印一次菜单本身（不是打印一次然后等输入），
选项用 `read -rp` 读入、`case` 分发到对应函数，直到用户选"应用"或"退出"才跳出循环：

```bash
main_menu() {
  while true; do
    clear_screen
    print_logo
    echo "$(msg menu_title)"
    echo "1) $(msg menu_option_a)"
    echo "2) $(msg menu_option_b)"
    echo "A) $(msg menu_apply)"
    echo "Q) $(msg menu_quit)"
    read -rp "$(msg prompt_choice) " choice
    case "$choice" in
      1) submenu_a ;;
      2) submenu_b ;;
      A|a) apply_settings; return 0 ;;
      Q|q) clear_screen; echo "$(msg bye)"; exit 0 ;;
      *) echo "$(msg invalid_choice)" ;;
    esac
  done
}
```

子菜单同理：自己的输入循环/一次性问答收集完就 `return`，回到主菜单继续下一轮。

## 2. 清屏规则

**每次切换菜单层级（主菜单→子菜单、子菜单→主菜单）以及退出时都要清屏**，不留上一层的回显。

用统一的 `clear_screen()`，`clear` 命令在非 tty 环境会报错，兜底成 ANSI 转义码：

```bash
clear_screen() {
  clear 2>/dev/null || printf '\033[H\033[2J' 2>/dev/null || true
}
```

调用位置：
- 主菜单循环体最开头（每轮重绘前）
- 每个子菜单函数最开头（进入子菜单时）
- 用户选"退出"那一行，`exit 0` 之前

"应用"（Apply）分支不清屏——那一步之后打印的是执行日志/校验结果，用户需要留着看，不算菜单层级切换。

## 3. 模块化 / 函数化

不写"从上到下顺序执行"的流水账脚本。按职责拆成独立函数，脚本主体只剩配置区
+ 函数定义区 + 最后一行 `main "$@"` 入口：

- 纯逻辑/生成类函数（不产生副作用）：比如拼 XML/生成配置片段的函数，只 `echo`/`cat <<XML` 输出，方便单独测试（可以 `source` 脚本后单独调用这个函数验证输出，不用跑整个脚本）
- 有副作用的动作函数：比如真正写文件、重启进程的函数，单独一个，不要和生成逻辑混在一起
- 每个子菜单一个函数，只负责收集这一组选项的输入，不做校验之外的其他事
- `main()` 函数做入口分发（无参数走菜单 / 带参数走直接应用），脚本最后一行只有 `main "$@"` 这一句

## 4. 国际化（i18n），默认英文

所有面向用户的输出文案都要过一层查表函数，**不要在业务逻辑里直接写死字符串**。
默认语言是英文，不管系统 locale 是什么；`--lang=zh` 显式切换成中文，
菜单里也留一个语言选项可以随时切换。

因为 bash 3.2 没有关联数组，查表用 `case` 语句实现，`LANG_SEL` 控制走哪个分支：

```bash
LANG_SEL=en   # 默认英文，--lang=zh 或菜单里选中文才变

msg() {
  local key="$1"
  if [ "${LANG_SEL}" = "zh" ]; then
    case "$key" in
      menu_title) echo "==== 主菜单 ====" ;;
      menu_quit)  echo "不应用，直接退出" ;;
      *) echo "$key" ;;   # 没翻译的 key 兜底显示 key 本身，方便发现漏翻
    esac
  else
    case "$key" in
      menu_title) echo "==== Main Menu ====" ;;
      menu_quit)  echo "Quit without applying" ;;
      *) echo "$key" ;;
    esac
  fi
}
```

用的时候 `echo "$(msg menu_title)"`。新加一条文案必须两个分支（en/zh）同时加，
不要只加一边——`*) echo "$key"` 兜底分支是用来暴露漏翻的 key 名字，不是长期方案。

## 5. 主界面 logo

主菜单第一次打印、以及每轮重绘时，先打印一个纯 ASCII 的 banner，再接标语
（标语走 `msg()`，logo 图形本身不含变量、不用翻译）：

```bash
print_logo() {
  cat <<'LOGO'
   ______           __
  / ____/  ______  / /___  _____
 / /_/ / / / / __ \/ __/ / / / _ \
/ __/ /_/ / / / / /_/ /_/ /  __/
/_/  \__,_/_/ /_/\__/\__,_/\___/
LOGO
  echo "  $(msg logo_tag)"
  echo
}
```

用 heredoc（`<<'LOGO'`，单引号防止里面的 `$`、反引号被展开）而不是一堆 `echo`，
改字体图案时不用逐行改代码。
